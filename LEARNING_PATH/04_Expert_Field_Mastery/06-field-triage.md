# 4.6 — Expert troubleshooting under time pressure

## Learning objectives

- Run a 15-minute triage protocol
- Communicate status to ops without overpromising
- Avoid shotgun online edits
- Know escalation triggers

**Time:** 6–8 h | **Prereq:** all prior  
**Lab:** `../../LABS/04-expert/LAB-4.6-timed-drills.md`  
**Scenarios:** `../../ON_THE_JOB/Scenarios/phase-04/`

---

## 15-minute triage

| Minute | Action |
|--------|--------|
| 0–2 | Safety, mode, what changed, what is the symptom *exactly* |
| 2–5 | Power, fault lights, controller fault, obvious field |
| 5–10 | Online: outputs/inputs for the failed device path |
| 10–13 | One hypothesis test (not five) |
| 13–15 | Stabilize, communicate, plan next window |

---

## Escalation triggers

- Safety system behavior unclear  
- Motion with unknown energy  
- No known-good program  
- Suspected network storm / multi-cell impact  
- You’re changing more than you’re measuring  

---

## Teach-back

> “Give a 30-second ops update that is honest and useful.”
